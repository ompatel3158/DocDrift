## 💡 Why DocDrift?

Outdated documentation is the single most common frustration in open source.
- A `README.md` instructs newcomers to run `npm run dev`, but the script was renamed to `npm run start` three months ago.
- An environment variable guide mentions `MONGO_URI`, but the application migrated to `DATABASE_URL`.
- A getting started section references `./config/settings.json`, but it was moved to `config/app.json`.
- A Docker command binds to port `8080`, but the service now listens on port `3000`.

**Hacktoberfest is about high-value contributions to open source.** Fixing documentation drift is one of the most appreciated contributions maintainers merge.

Most AI tools try to generate whole pages of documentation from scratch. **DocDrift verifies existing documentation against ground-truth code.**

```
Documentation Claims  ──>  [ Gemma 4 Extractor ]  ──>  Checkable Claims (Paths, Scripts, Envs, Ports)
                                                                │
                                                                ▼
Codebase Ground Truth ──>  [ Deterministic Verifier ] ──>  True Verdict + Evidence
                           (Python, AST, Manifests)             │
                                                                ▼
Outdated Claims (DRIFT) ──> [ Gemma 4 Surgical Fixer ] ──> In-Place Fix + Git Diff + PR Description
                                                                │
                                                                ▼
Persistent Cache      ──>  [ UltSQL Memory Engine ]   ──>  HNSW Vector RAG + KV + NoSQL History
```

## ✨ Key Features

### 1. Zero Hallucination: Deterministic Code Verification
Verdicts (**`VERIFIED`** vs **`DRIFTED`**) are **never generated by an LLM**. They are computed strictly by plain Python code inspecting actual files, parse trees, and package manifests. The AI model cannot hallucinate a "true".

### 2. Powered Exclusively by Gemma 4
DocDrift strictly targets Google DeepMind's **Gemma 4** open-weights models (`gemma-4-26b-it` and `gemma-4-31b-it`) via the Gemini API:
- **Claim Extraction**: Maps natural documentation text into typed structured claims (`FILE_PATH`, `COMMAND_SCRIPT`, `ENV_VAR`, `DOCKER_PORT`, `CLI_FLAG`).
- **Surgical Line Rewriter**: Rewrites *only* the drifted token, preserving original indentation (spaces/tabs), backticks, formatting, and surrounding prose.

### 3. Converged Memory Engine (UltSQL + Local Fallback)
DocDrift features a high-performance persistent memory subsystem:
- **Key-Value Store**: Sub-microsecond caching of documentation and section hashes (`docdrift:hash:<path>` -> SHA-256).
- **NoSQL Document Collections**: Persistent `claims_history` collection with JSON filtering for tracking drift over time.
- **Relational SQL Tables**: Indexed `manifest_scripts` and `repo_symbols` relational catalogs.
- **Native HNSW Vector RAG**: Embeddings with semantic synonym expansion (e.g. `MONGO_URI` ↔ `DATABASE_URL`, `PORT_NUM` ↔ `PORT`, `API_SECRET_KEY` ↔ `JWT_SECRET`) for finding renamed variables.
- **Local Fallback**: Automatically falls back to an embedded SQLite engine when UltSQL daemon is not active.

### 4. Multi-Ecosystem Manifest Verification
Verifies commands and scripts across all major developer ecosystems:
- **Node.js / TypeScript**: `package.json` scripts (`npm`, `yarn`, `pnpm`, `bun`).
- **Python**: `pyproject.toml` (Poetry, Hatch, PDM, Flit), `setup.py`, `uv`, and module execution (`python -m`).
- **Docker**: `docker-compose.yml`, `compose.yaml`, and `Dockerfile` port mappings.
- **Rust**: `Cargo.toml` bins and examples (`cargo run --bin`).
- **Go**: `go.mod` package entrypoints (`go run`).
- **Make**: `Makefile` targets.

### 5. Safe Sandboxed Command Prober ("Knowing Running Commands")
For claimed command invocations:
- **PATH Toolchain Verification**: Validates whether required binaries (`docker`, `cargo`, `go`, `make`, `uv`) are available.
- **Dry-Run Probing**: Executes non-destructive checks (e.g. `make -n <target>`, `<binary> --help`) within a 3-second sandboxed timeout.
- **Dangerous Token Blacklist**: Strictly rejects and halts commands containing destructive tokens (`rm -rf`, `del`, `sudo`, `chmod`, `dd`, `mkfs`, fork bombs, piping curl into bash).

### 6. Interactive Split-Diff Reviewer
Run `docdrift review` for an interactive, side-by-side terminal experience powered by Rich:
- Left panel displays the outdated line with syntax highlighting and proof evidence.
- Right panel displays Gemma 4's proposed surgical fix.
- Interactive actions: `[a]` Accept, `[e]` Edit manually, `[s]` Skip, `[q]` Quit.

### 7. Continuous Watch Loop (`docdrift watch`)
Run DocDrift as a standing monitor with periodic Git remote pulling (`--pull <seconds>`), live terminal dashboards, and optional automatic in-place patching (`--fix`).

## 🚀 Quick Start

### Installation

```bash
# Clone the repository
git clone https://github.com/your-org/docdrift.git
cd docdrift

# Install dependencies using uv (recommended)
uv pip install -e .

# Or using standard pip
pip install -e .
```

### Configure Gemma 4 (Gemini API)

Set your Gemini API key (Gemma 4 models run via the Gemini API endpoint):

```bash
# On Linux/macOS
export GEMINI_API_KEY="your-api-key"

# On Windows (PowerShell)
$env:GEMINI_API_KEY = "your-api-key"
```

> **Note**: DocDrift also includes a complete **offline heuristic mode** (`--offline`) that works without any API key using regex extractors and deterministic fixers!

## 🖥️ CLI Usage & Commands

### 1. `docdrift check` — Scan and Verify

Scan documentation claims against the repository:

```bash
# Check current directory
docdrift check

# Check a specific local directory
docdrift check ./my-project

# Check a remote GitHub repository directly (shallow clones and cleans up)
docdrift check https://github.com/pallets/flask

# Run in offline mode (no API key required)
docdrift check . --offline

# Generate unified git diff of proposed fixes
docdrift check . --diff

# Generate a ready-to-merge GitHub PR description
docdrift check . --pr

# Automatically apply surgical fixes in-place
docdrift check . --fix

# Export structured JSON report
docdrift check . --json report.json
```

### 2. `docdrift review` — Interactive Split-Diff Review

Step through drifted claims one by one in an interactive terminal dashboard:

```bash
docdrift review .
```

```
Outdated Line (Line 15)                  Proposed Replacement (Gemma 4)
─────────────────────────────────────   ─────────────────────────────────────
Run the dev server:                     Run the dev server:
`npm run dev`                           `npm run start`

Evidence: Script 'dev' not in           Surgical replacement: 'dev' -> 'start'
package.json. Available: start, build

Action: [a]ccept  [e]dit  [s]kip  [q]uit > a
✔ Applied fix in place to README.md (Line 15)
```

### 3. `docdrift watch` — Continuous Monitoring Loop

Monitor your documentation for drift as code changes, with optional periodic git pulling:

```bash
# Watch local directory for changes
docdrift watch .

# Poll and git pull from origin every 60 seconds
docdrift watch . --pull 60

# Watch and automatically fix drift in-place
docdrift watch . --fix
```

### 4. `docdrift memory` — Cache & Vector Diagnostics

Inspect or reset DocDrift's persistent UltSQL/local memory cache:

```bash
# View cache statistics
docdrift memory .

# Clear persistent cache
docdrift memory . --clear
```
